## `src/mossaudit/client.py`

Raw HTTP client for Moss Inference with byte-level timing.

Why not the SDKs for measurements: an SDK hides when the first byte and the first text delta arrive and
adds its own retries. Here every call is one HTTP exchange. The request is fully built first; the clock
`t0` starts immediately before `send`. All times are `time.perf_counter()` offsets from t0, in ms:

  t_headers       status line + headers received
  t_first_byte    first body chunk received from the socket
  t_first_event   first COMPLETE SSE event (dispatched at its blank-line delimiter)
  t_first_token   first complete event carrying non-empty text (Responses `response.output_text.delta`,
                  Chat `choices[0].delta.content`)  -> the "client time to first text delta" (TTFT)
  t_terminal      the terminal event (Responses completed/incomplete/failed, Chat `[DONE]`)
  t_end           stream closed / body read

Each event is timestamped with the arrival time of the chunk that completed it, so a frame split over
several TCP reads is dated when its last byte arrived. Multi-line `data:` fields are joined per the SSE
spec. `stream_outcome` says how a stream ended: completed | incomplete | failed | done | error_event |
closed_early (we stopped on purpose) | eof_no_terminal | unexpected_done | read_error.
An event missing its blank-line delimiter at EOF is discarded and logged as `<incomplete-frame>`.

httpx's trace extension tells whether the call opened a new connection; `connect_ms` covers TCP connect
only (DNS is separate in httpx 0.28 and not isolated here). Only a whitelist of response headers is
kept and the Authorization header is never logged. Response bodies ARE kept as received, so raw logs
can contain whatever the API sent back: publish them only through scripts/redact.py.

### class `CallRecord`

Everything logged about one HTTP exchange: request, status, kept headers, timings and body.

#### `to_json(self) -> str`

Serialise the record as one JSON line.

### class `MossHTTP`

Thin httpx wrapper that sends one request per `call()` and times it at the byte level.

#### `__init__(self, creds: Credentials | None, base_url: str=BASE_URL, timeout: float=120, transport: httpx.BaseTransport | None=None, bearer_override: str | None=None)`

#### `close(self) -> None`

Close the underlying connection pool.

#### `call(self, method: str, path: str, body: Any=None, headers: dict[str, str] | None=None, raw_content: bytes | None=None, stop_after_first_token: bool=False, tag: dict[str, Any] | None=None, drain_after_done: bool=False, timeout_s: float | None=None) -> CallRecord`

Send one request and return its CallRecord.

All times are milliseconds after the request is handed to httpx (`t0`, see the module
docstring). TTFT is `t_first_token_ms`: the first COMPLETE event that carries non-empty text.
`timeout_s` applies per httpx operation (connect, read, write), not to the whole call.
With `stop_after_first_token` the stream is closed on purpose after that event
(`stream_outcome = "closed_early"`); with `drain_after_done` reading continues after
`[DONE]` to catch trailing frames. An API refusal (4xx/5xx) is a normal record: see
`rec.status` and `rec.body`. Transport errors and malformed streams are recorded in
`rec.error` / `rec.stream_outcome` instead of being raised.

## `src/mossaudit/ledger.py`

Append-only spending ledger that reserves money before every paid send.

Row kinds (one JSON object per line, never rewritten):
  reserve  {key, usd}            money set aside before a send; counts until released
  release  {key}                 the reservation is over (call settled, or request refused)
  charge   {usd, key?}           a settled cost (inference: from `usage` and documented prices)
  task     {task_id, usd, key?}  a cumulative cost snapshot of a task; the MAX per task counts,
                                 so a stale or missing (zero) snapshot can never lower known spend

Exposure = charges + max task snapshot per task + whatever part of each open reservation is not
yet covered by the task it belongs to. Every paid send must first `reserve()`; the check and the
reservation happen under an exclusive file lock, so two processes cannot both pass the same check.
Non-finite or negative amounts are refused (a NaN would make every comparison fail open).

### class `BudgetExceeded`

A reservation would push exposure above the cap; nothing was sent.

### class `HoldBlocked`

A reservation was refused because a blocking hold (e.g. an unresolved task create) is open.

### class `Ledger`

File-locked, append-only record of reservations and costs (see the module docstring).

Three amounts matter: settled dollars (charges + task costs), open holds not yet covered by a
task cost, and exposure = their sum, which is what the cap is checked against. The lock is a
POSIX `flock` on the ledger file, so it protects processes on one machine only.

#### `__init__(self, path: Path=LEDGER_PATH, cap_usd: float | None=None) -> None`

#### `state(self) -> dict[str, Any]`

Recompute charges, task costs, open reservations and total exposure from the file.

#### `spent(self) -> float`

Exposure: settled spend plus open reservations (what the cap is checked against).

#### `reserve(self, campaign: str, key: str, usd: float, block_prefix: str | tuple[str, ...] | None=None) -> None`

Hold `usd` under `key`. With `block_prefix`, refuse (under the same lock) while any open
hold starts with that prefix: this is how "one unresolved task at a time" is made atomic.

#### `swap(self, campaign: str, old_key: str, new_key: str, usd: float) -> bool`

Replace one hold by a smaller one in a single locked step (no window without a hold).

Used when a task ends: its create hold becomes a traffic hold. If the new hold would be larger
than the old one, the old one is kept, nothing changes and False is returned.

#### `open_holds(self, prefix: str='') -> dict[str, float]`

Open reservations whose key starts with `prefix`, as {key: usd}.

#### `release(self, key: str, **evidence: object) -> None`

Close a reservation; `evidence` is stored with the row.

#### `charge(self, campaign: str, usd: float, key: str | None=None, **extra: object) -> None`

Book a settled cost; if `key` is given, its reservation is released in the same step.

#### `task_snapshot(self, campaign: str, task_id: str, usd: float, key: str | None=None, **extra: object) -> None`

Record the cumulative cost of a task; only the highest snapshot per task counts.

#### `guard(self, estimate_usd: float, campaign: str) -> None`

Pre-flight sanity check of a whole campaign (each send still reserves on its own).

## `src/mossaudit/tasks.py`

Tasks API harness: bounded create, poll with state-transition timing, cancel, cost ledger.

Safety rules enforced here:
- Before a create is sent, a worst-case bound for the task is reserved in the ledger, and the
  Idempotency-Key + body are written to the raw log. An ambiguous create (transport error, 5xx, 408,
  429) is retried with the SAME key and body, so it can never start a second task.
- Only one task may be unresolved at a time: `create` refuses while an earlier task is not terminal.
- `wait` enforces its deadline on every poll outcome (errors included, and polls answering for another
  task id count as errors), honours Retry-After, cancels once at `max_wait_s`, and gives up 120 s
  later, leaving the task unresolved with its hold. Every HTTP call inside gets at most 30 s per
  httpx operation (connect/read/write), capped by the time left; this bounds each step, it is not a
  hard wall-clock guarantee for a slowly trickling reply.
- `cleanup()` (also run on context exit, even after an exception) cancels and settles open tasks.
- After a task ends, its hold is swapped (atomically) for a small traffic hold kept until the portal
  Usage page is reconciled (scripts/reconcile.py), because traffic can be billed after the task
  ends. A task that ends without a reported cost keeps its full hold (re-keyed `unpriced:<id>`).
- Across restarts, any open `task-create:` hold in the ledger blocks new creates until recovered.

Polling (`GET /v1/tasks/{id}`) is not billed per the docs; each poll is still logged.

### class `UnresolvedTask`

A create may have reached Moss but its outcome is unknown; its reservation stays open.

### `task_cost(task: dict[str, Any]) -> float | None`

The task's reported total cost, or None when the body carries no cost at all.

### `task_bound(body: dict[str, Any]) -> float`

Worst-case cost we are willing to believe for one task created from `body`.

Model spend: max_cost_usd (default $2) x markup x overshoot factor; browser: the runtime cap at
$0.02/h; traffic: a fixed allowance. Values the API should refuse are clamped to the documented
range, so a wrongly accepted value is still budgeted at the range edge.

### class `TaskRunner`

Creates, polls, cancels and books Tasks API runs under the ledger's budget rules.

#### `__init__(self, http: MossHTTP, ledger: Ledger, log: RunLog, campaign: str) -> None`

#### `create(self, body: dict[str, Any] | bytes, headers: dict[str, str] | None=None, tag: dict[str, Any] | None=None, idempotency_key: str | None=None, bound_usd: float | None=None, max_attempts: int=3, idempotency_test: bool=False) -> CallRecord`

Reserve the task's worst case, save the intent, then send the create.

An ambiguous outcome is retried with the same Idempotency-Key and body, up to
`max_attempts`; if still ambiguous, UnresolvedTask is raised and the hold stays open.

#### `recover(self, max_attempts: int=3) -> dict[str, Any]`

Replay unresolved creates with their exact bytes and Idempotency-Key, on the existing hold.

Same key + same body returns the original task (documented replay, keys live 24 h per
project), so this never starts a second task. Only a returned task id clears the hold: any
refusal on replay says nothing about the first attempt, so the hold is kept. Intents that are
too old or belong to another project are not replayed; they and holds without an intent are
reported for a manual portal check (scripts/reconcile.py --after-portal-check), and so are
intents of the deliberate idempotency test (I1), which are never resent.

Returns {"recovered", "kept", "manual"}. A recovered task may still be running: it is back
in `self.open`, and the caller must `wait()` on it before creating another task.

#### `replay(self, payload: bytes, key: str, expected_id: str | None, bound_usd: float, tag: dict[str, Any], http: MossHTTP | None=None) -> CallRecord`

Send a create that reuses `key`, under its own fresh `task-create:` hold and intent.

The hold is taken before sending, so the create gate, recover() and reconcile.py all protect
it if the process dies. Outcomes: same id as `expected_id` -> the extra hold is released with
that proof (the original hold stays); a new id -> it stays open under this hold (the caller
cancels it); a definitive refusal (e.g. 422) -> released; anything ambiguous -> the hold is
kept and UnresolvedTask is raised by _send_create.

#### `get(self, task_id: str, tag: dict[str, Any] | None=None, timeout_s: float | None=None) -> CallRecord`

GET /tasks/{id} and log it.

#### `cancel(self, task_id: str, tag: dict[str, Any] | None=None, timeout_s: float | None=None) -> CallRecord`

POST /tasks/{id}/cancel and log it.

#### `wait(self, task_id: str, poll_s: float=3.0, max_wait_s: float=900, cancel_after_s: float | None=None, cancel_on_status: str | None=None) -> dict[str, Any]`

Poll until terminal. Returns the last task body plus `_trace` (status transitions).

At `max_wait_s` the task is cancelled once, then polled for up to 120 s more. If it is still
not terminal, the last body is returned and the task stays unresolved with its hold (check
`task_id in runner.open`). A terminal task is booked and settled as a side effect: its
create hold is swapped for a small traffic hold (see `_settle`).

#### `cleanup(self) -> None`

Cancel and settle any task still open (runs on context exit, also after errors).

Raises UnresolvedTask if a task is still open afterwards, so the run is reported failed.

### `benchmarks/inference/cache.py`

```
INF-05: reply-cache semantics (docs: "A repeated request answered without a model call, free";
a hit "reports 0 prompt tokens"; `X-Moss-Cache: off` skips it).

Every run starts from a fresh nonce in the prompt, so the first call of each base request is a miss.
Calls are sequential and paced (1 s between starts). For each call we keep status, usage, every
response header (to find any hit flag besides the token count), the reply text and timings.

Each comparison gets its own nonce, primed with two identical calls (the second must be a hit), so
earlier probes cannot influence it. Base = Responses, non-stream, fastlane, max_output_tokens 24,
X-Moss-Retrieve: off.
  A  n1: base x5, cache on                   -> A2..A5 expected hits
  B  n1: base, X-Moss-Cache: off             -> must call the model
  C  n2: prime x2, then input + one space    -> exact-text key? (observe)
  D  n3: prime x2, then max_output_tokens 25 -> parameters in the key? (observe)
  E  n4: prime x2, then stream: true         -> non-stream reply reused by a stream? (observe)
     n5: stream x2                           -> stream-to-stream reuse? (observe)
  F  n6: prime x2 on Responses, then the same prompt on Chat x2
                                             -> shared across endpoints? Chat-to-Chat reuse?
  G  n7: X-Moss-Cache: off x3, then cache on x2
                                             -> G4 hit = cache-off calls populate the cache;
                                                G5 hit after a G4 miss = G4 populated it.
A hit is: HTTP 200, a completed reply with non-empty text, and usage input tokens == 0. Every kept
response header is logged (client keeps x-moss-*, age, x-cache*, cache-control) to look for a flag.
A 429 waits its full Retry-After before the next call; above 60 s the run stops.

Run:  python benchmarks/inference/cache.py
```

### `benchmarks/inference/grounding.py`

```
INF-08: does retrieval ground the answer? Fictional facts, grounded arm vs retrieval-off arm.

Data: benchmarks/inference/data/fictional_facts.json (30 invented facts in index `audit-facts`, 30
answerable questions, 10 questions about entities that are NOT in the index). Every entity and number
is invented, so a correct answer in the plain arm can only be a lucky guess.

Arms (same call, same headers except one): both name `X-Moss-Indexes: audit-facts`; the plain arm
adds `X-Moss-Retrieve: off`. Order of (question, arm) is shuffled with a fixed seed. Reply cache off.
Output uses `text.format` json_schema {answer: string|null, found: boolean} (merges INF-07).

Scoring (exact, no judge model):
- answerable: correct iff found is true and normalize(answer) == expected exactly (normalize: trim,
  casefold, trailing '.', one trailing unit word); every expected value is unique in the fixture;
- unanswerable: correct iff found is false AND answer is null; found:true is a hallucination;
- found:false with a non-null answer (or found:true with null) is "inconsistent"; a Responses status
  other than completed is "response_<status>", never scored.
Also logged: X-Moss-Retrieve-Ms, input tokens per arm (retrieved facts count as input), schema
validity of output_text.

Run:  python benchmarks/inference/grounding.py [--limit N]
```

### `benchmarks/inference/latency.py`

```
INF-02 / INF-03 / INF-04: time to first token (TTFT) and total time, streamed, per condition.

Design
- Conditions (model x grounded x prompt size) are interleaved in a seeded random order, so drift over
  time (load, network) spreads across conditions instead of biasing one of them.
- One keep-alive HTTP/1.1 connection, sequential calls: TTFT then excludes TCP/TLS setup, which is
  logged separately when a call had to open a new connection.
- `X-Moss-Cache: off` on every call, so the reply cache cannot answer; `usage.input_tokens > 0` checks it.
- Warm-up calls (first `--warmup` per condition) are kept in the raw file with `warmup: true` and left
  out of the summary.
- With --index, questions come from the INF-08 fixture (answerable ones), the same in both arms.
- Pacing: --min-interval between authenticated starts; a 429 waits its full Retry-After, and one above
  60 s stops the campaign. Rate-limited units are not retried.
- Rejection-path TTFB: every `--floor-every` calls, an unauthenticated POST /v1/responses that the
  server refuses (free). Reported only as context ("how fast does the front door answer"); it is NOT a
  lower bound of server time and nothing is subtracted from TTFT.
- Budget: each call reserves its worst case (prompt + bounded retrieved context + max output) before
  it is sent; the settled cost replaces the reservation. If a reply carries no usage (failed or
  truncated stream), the full reservation is booked as spent and the row is flagged.

TTFT = time from just before the request is written to the first non-empty text delta (see client.py).

Run:  python benchmarks/inference/latency.py --models moss/fastlane-1 --n 100 --warmup 10
```

### `benchmarks/tasks/validation.py`

```
TSK-08: request validation of POST /v1/tasks, against the Tasks API reference.

Order of a run
1. Control: one known-good create with an immediate cancel attempt. If the create is rejected, stop
   so an entitlement or gateway failure cannot be mistaken for a validation verdict.
2. Rejection cases: each should be refused before a task exists, so it costs nothing. A case that is
   accepted anyway (a real finding) is cancelled at once and waited to a terminal state before the next
   case; its cost is booked. Each create reserves its worst-case bound first (see mossaudit.tasks).
3. Acceptance boundary: goal of exactly 20,000 characters, created then cancelled at once.

The expected `code or type` comes from the reference's error table: 400 -> invalid_request_error,
model_not_found or model_not_enabled; 413 -> invalid_request_error.

Deliberately NOT tested
- start_url values pointing at internal hosts or local files (127.0.0.1, file://, javascript:): if
  accepted they would make Moss's browser touch Moss's own infrastructure, i.e. security testing that
  is out of scope.
- Cost-cap cases (max_cost_usd 0, 0.009, "0.01", 50.01) and max_runtime_seconds 7201: if wrongly
  accepted or silently replaced by the $2 default, the task would run with a bound the audit cannot
   justify. The cost cap is exercised only by valid values in TSK-04.

Run:  python benchmarks/tasks/validation.py
```

### `scripts/reconcile.py`

```
Show the ledger state and close holds after checking the portal Usage/Billing pages.

  python scripts/reconcile.py                       # print settled spend, open holds, tasks
  python scripts/reconcile.py --release traffic:task_x [--portal-usd 0.012 --note "Usage 14:05Z"]

`--portal-usd` books the extra amount the portal shows for that one item (for example the traffic
charge of one task) as a settled charge, then releases its hold. It takes exactly one --release key,
so one portal amount can never be booked several times.
```

### `scripts/redact.py`

```
Make a publishable copy of the raw logs: results/raw/*.jsonl -> results/logs/*.jsonl.

Each line is parsed as JSON and walked value by value:
- the Moss project id and project key from .env  -> "<project_id>" / "<project_key>";
- any "Bearer ..." value                         -> "Bearer <redacted>";
- any moss_ + 32 hex token                       -> "<project_key>";
- an `existing_indexes` list (the project's own index names) -> `existing_indexes_count`.

Every redacted copy, and every file already in results/processed/, is then checked (after JSON
decoding) for the id, the key, both token patterns and index names. If anything is found the script
stops before writing a single file.
It checks known credentials and patterns only; it does not scan git history.
results/raw/ itself stays git-ignored.

Run:  python scripts/redact.py
```
